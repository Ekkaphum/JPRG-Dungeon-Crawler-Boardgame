> อ้างอิง `../../GAME_DESIGN_v0_3_0.md` (หัวเอกสารเขียนว่า v0.4.1 — ดู PLAN §6)

## 1. สกิล Lv2 (§7.2) — ไม่มีตัวเลขในเอกสารต้นฉบับ

**ตัดสิน:** ทำ **ทางเลือก A จากแผน** — ใส่ตัวเลข Lv2 ให้ครบทั้ง 12 ใบ (ประมาณ +35–50% พลัง เทียบ Lv1)
เพื่อให้ระบบ EXP มีความหมายจริงตามที่เอกสารตั้งใจ (§7) แทนที่จะปิดทั้งระบบทิ้ง
**ตัวเลข Lv2 ทั้งหมด "ไม่ได้มาจากเอกสารต้นฉบับ" เป็นการประมาณเพื่อให้เล่นได้ — ต้อง balance-test ซ้ำก่อนเชื่อ**
ดูตารางเต็มใน `src/content/characters.ts`

กติกาเดียวที่เอกสารระบุไว้จริง (§5.2): **สกิลที่มี 🎲 (มีแค่ Quick Shot) เมื่อเป็น Lv2 เริ่มบันไดเต๋าที่ 4+ แทน 5+**

## 2. ระบบ 🎲 ใช้กับสกิลไหน

**ตัดสิน:** ตามเอกสารตรงตัว — มีแค่ **Quick Shot** ใบเดียวที่มี 🎲 บันไดเต๋า 5 ขั้นของ §5.2 เขียนเป็นระบบทั่วไป
ในโค้ด (`skill.roll` field) เผื่ออนาคตเพิ่มใบอื่น แต่ v0.3.0 ใช้กับ Quick Shot เท่านั้น

## 3. กฎเสมอ (§12 ข้อ 2)

**ตัดสิน:** รับข้อเสนอของเอกสารเอง — **"หมากอยู่สูงกว่าบนนาฬิกาถือว่ามากกว่าเสมอ"** ใช้กับทุกกรณีเปรียบเทียบ
(HP ต่ำสุด, หมากสูงสุด, คะแนนนำ) **ถ้ายังเสมอ (ซ้อนกองเดียวกัน) → ใครอยู่ล่างกอง (วางก่อน) ชนะ**
Implement เป็น comparator กลาง `pickExtreme()` ใช้ซ้ำทุกจุด — ดู `src/engine/clock/rank.ts`

## 4. ปุ่มแก้สมดุล §11 (8 ข้อ)

**ตัดสิน:** ไม่ทำเป็นระบบ toggle ที่ผู้ใช้เปิดได้จากหน้าตั้งค่า (ตัดจากแผนเดิมเพื่อลดขอบเขต) —
ใช้ค่าตั้งต้นของเอกสารตรงๆ ทุกจุด ถ้า balance sim (M8) พบว่าพัง จะแก้ค่าดิบใน `content/` โดยตรงและบันทึกใน
`BALANCE_NOTES.md` แทน (ง่ายกว่าระบบ flag สำหรับ scope ของรอบนี้)

## 5. ⚠️ กติกาที่ไม่ได้เขียนตรงๆ ในเอกสาร — ต้องตัดสินเพื่อ implement ได้

เอกสารกำหนด **โมเดล "ประกาศตอนนี้ → ผลเกิดตอนมาเยือนครั้งหน้า"** ไว้ชัดเจนระดับภาพรวม (§4.2) แต่ไม่ได้ระบุ
ว่า **ทุกสกิลดีเลย์เท่ากันหมดหรือไม่** — อ่านตัวอย่างเชิงกลยุทธ์ใน §4.4/§8 แล้วสรุปว่า **ไม่เท่ากัน**:
สกิลมี 2 กลุ่มพฤติกรรมต่างกัน

### กลุ่ม A — ดีเลย์เต็ม (ผลเกิดตอนมาเยือนครั้งหน้าเท่านั้น)
ดาเมจ/ฮีลที่ส่งไปหาเป้าหมาย (ตัวเอง หรือคนอื่น หรือบอส): Slash, Berserk, Twin Shot, Fireball, Meteor,
Smite, Quick Shot (ทั้งดาเมจและการทอยเต๋าเปิดจุดอ่อน), Heal, และ "หมัดสวน" ของ Counter Attack (ถ้าเกิดขึ้น)

**เหตุผล:** ตัวอย่าง §5.5 ("Luna ประกาศ Heal ใส่ Matt → Matt ตายก่อนถึงคิว → Heal หายไปเฉยๆ") ใช้ได้ก็ต่อเมื่อ
Heal ยังไม่เกิดผลจนกว่าจะถึงตาของ Luna อีกครั้ง — ยืนยันว่ากลุ่มนี้ดีเลย์จริง

### กลุ่ม B — มีผลทันทีตอนประกาศ (สถานะ/ทรัพยากรของตัวเอง)
Counter Attack (ตัวลดดาเมจ -50%), Blessing (บัฟ +3/-2 ทั้งวง), ManaCharge (Mana+1 และตัวลดดาเมจ -3),
Set Trap (วางโทเคนบนกระดาน)

**เหตุผล:** ข้อความในการ์ดเองระบุ "**จนถึง**เทิร์นหน้าของคุณ" — แปลว่าช่วงเวลาที่บัฟ *active* เริ่มนับตั้งแต่ตอนประกาศ
ไม่ใช่ตอนเทิร์นหน้า (ถ้าบัฟเริ่มทำงานตอนเทิร์นหน้าแทน ก็จะไม่มีอะไรป้องกันช่วงที่บอสตีระหว่างทาง ซึ่งขัดกับ
คำอธิบายของ Matt เองว่า "Counter ไม่ใช่การเสี่ยงดวง เพราะแอคชันบอสเปิดเผย — มันคือการอ่านเกม" (§8) — เขาต้อง
ป้องกันได้ *ก่อน* ที่บอสตีจริง ไม่ใช่หลังจากรอบถัดไปผ่านไปแล้ว) และตัวอย่างคอมโบใน §8 ("จัดคิวบนนาฬิกาให้ตรงเป๊ะ"
ระหว่าง Kit เปิดจุดอ่อน + Luna เปิด Blessing + Vera ยิง Meteor) ก็ใช้ได้เฉพาะถ้า Blessing active ทันที

**สถานะกลุ่ม B ทั้งหมดหมดอายุที่จุดเดียวกัน:** ตอนที่ pending ของสกิลนั้นถูก "รับผล" ที่การมาเยือนครั้งหน้าของ
ผู้ประกาศเอง (สำหรับ Counter คือจุดที่เช็คว่าโดนตีระหว่างนั้นไหมด้วย) — ระยะเวลาบัฟ = ระยะเวลาที่ pending ค้างอยู่พอดี

### แก้กติกาภายหลัง — Counter Attack และ Set Trap (ผู้ใช้สั่งเปลี่ยน)

**Counter Attack ไม่ใช่กลุ่ม B แบบ "รอจ่ายตอนเทิร์นหน้า" อีกแล้ว** — ตัวลดดาเมจยังมีผลทันทีตอนประกาศ
เหมือนเดิม แต่การสวนกลับเกิด **ทันทีทุกครั้งที่โดนตี** (โดน 3 ครั้ง = สวน 3 ครั้ง) และเมื่อถึงเทิร์นของตัวเอง
รอบหน้าคือแค่หมดฤทธิ์ ไม่มีการตีเพิ่ม

**ตัดสิน: สวนกลับทำงานแม้เป็นหมัดที่ฆ่า Matt ตาย** — ถ้าไม่ให้ทำงาน บอสจะ "หลบ" การสวนได้ด้วยการตีให้ตาย
ซึ่งกลับหัวกลับหางกับเหตุผลที่มีสกิลนี้ (ยิ่งบอสตีแรง ยิ่งควรโดนสวน) โค้ดอ่านค่า counterDmg ไว้ก่อนคิดดาเมจ
เพราะ `killFighter` เคลียร์ shield ทิ้ง

**หมายเหตุที่ต้องรู้:** การสวนกลับวิ่งผ่าน `computeOutgoingPlayerDamage` เหมือนการโจมตีปกติ แปลว่า
**ได้รับ Blessing (+atk) และจุดอ่อนเปิด (+4) ด้วย** — ค่า 12 จึงกลายเป็น 19 ได้ถ้าวงบัฟครบ

**Set Trap เปลี่ยนเป็นสกิลแบบหน้าต่างเวลาเหมือน Counter** — ⏱5, เลือกวางกับดักได้ 1 ช่อง
**เฉพาะภายในช่วง ⏱ ของสกิลเอง** (ไม่ใช่ทั้งนาฬิกาแบบเดิม), ทำดาเมจ 4 (Lv2 = 6) และถ้าโดนจะ **ทอย d6
ยกเลิกท่าที่บอสประกาศไว้** ด้วยบันไดเต๋าชุดเดียวกับ Quick Shot (5+ / ง่ายขึ้น 1 ต่อการพลาด / ครั้งที่ 5 อัตโนมัติ)
— จากเดิมที่ยกเลิกให้อัตโนมัติ 100%

**ผลข้างเคียงเชิงกติกาที่ควรรู้:** หมากบอสขยับเฉพาะตอนถึงตาตัวเอง ดังนั้น **วางกับดักทับช่องที่บอสยืนอยู่
= โดนแน่นอน 100%** (วัดจริงได้ 97.4%) ความยากจึงไม่ได้อยู่ที่ "เดาให้ถูก" แต่อยู่ที่ "บอสอยู่ในระยะ ⏱5 ไหม"
ซึ่งวัดได้ 86.8% ของตาที่ Kit ได้ประกาศ

### ข้อยกเว้นเดี่ยว — "จุดอ่อนเปิด" ของ Quick Shot
แม้ Quick Shot เองอยู่กลุ่ม A (ดาเมจ+การทอยเต๋าดีเลย์เต็ม) แต่ **ผลลัพธ์ของการทอยที่สำเร็จ** (บัฟ "จุดอ่อนเปิด"
+4 โจมตีผู้เล่นทุกคน) มีอายุตาม "จนกว่าบอสจะทำแอคชันถัดไป" — ผูกกับนาฬิกาของบอส ไม่ใช่ของ Kit
⇒ เริ่ม active ทันทีที่ Quick Shot **รับผลจริง** (ที่การมาเยือนครั้งหน้าของ Kit) และหมดอายุตอนที่ **pending ของบอส
ถูกรับผล** ครั้งถัดไป (นับเป็นครั้งที่บอส "ทำแอคชัน" จริง)

## 6. รายละเอียดกลไกที่ implement ตรงตามเอกสาร (บันทึกไว้กันลืม)

- **Rage (Ragorath):** +1 ทุกครั้งที่บอสโดนดาเมจ (แม้ดาเมจ 0) · รีเซ็ตเป็น 0 **ทันทีหลัง** บวกเข้าดาเมจของ
  แอคชันบอสตัวเองที่กำลังรับผล (ลำดับ: dmg = base + rageปัจจุบัน → apply → rage = 0)
- **มนตร์ง่วงงุน (Somnivar):** +2 ช่องเดินก็ต่อเมื่อ **ผู้เล่น** ประกาศสกิล ⏱ ≥ 5 (ไม่กระทบแอคชันของบอสเอง)
  คิดตอนประกาศ (ปลายทางเปลี่ยนทันที ไม่ใช่คิดตอนรับผล)
- **เกราะ Aurelius:** ลดดาเมจทุกครั้งที่เข้าใส่ (ยกเว้น Smite และ Set Trap ซึ่งไม่สนเกราะทั้งคู่) · เช็ค
  "ดาเมจหลังหักเกราะ > 12" ทุกครั้งที่โดนตีแบบปกติ (ไม่ใช่แค่ตอนเดียว, ไม่นับดาเมจที่ไม่สนเกราะเพราะไม่ผ่านการหักเกราะ)
  → เกราะ -1 ถาวรทันทีที่เข้าเงื่อนไข (ต่ำสุด 0)
- **กับดัก Kit:** วางในช่วง ⏱ ของสกิลตอนประกาศ (ไม่ดีเลย์) · เช็คทุกช่องที่มาร์กเกอร์เดินผ่าน: บอสอยู่ตรงนั้นพอดี → ทำงาน
  (primary dmg ไม่สนเกราะ + ทอยยกเลิก pending ของบอส) · บอสไม่อยู่ตรงนั้น (เดินผ่าน) → ลบกับดักทิ้ง
- **ตาย/ฟื้น:** ตำแหน่งฟื้น = (ช่องที่ตาย − 6) ต้อง ≥ 0 ถึงจะฟื้นในยกนี้ · ฟื้นด้วย HP ครึ่งหนึ่งปัดขึ้น ·
  ประกาศแอคชันใหม่ได้ทันทีไม่มีอะไรให้รับผล
- **บัฟ "ทุกคน":** หมายถึงผู้เล่นเท่านั้น ไม่รวมบอสเสมอ (§5.1)

### แก้กติกาภายหลัง รอบ 2 — Set Trap ไม่สนเกราะ, ⏱4, เพดานเกราะแตก Aurelius ลดเหลือ 12 (ผู้ใช้สั่งเปลี่ยน)

หลังรัน balance sim รอบแรก (win rate 14.6%) พบว่า Set Trap ทำดาเมจต่อ ⏱ แย่กว่าสกิลอื่นมาก และเพดานเกราะแตก
ของ Aurelius (> 15 หลังหักเกราะ) แทบไม่มีทางถึงจริงเพราะดาเมจต่อครั้งของบอทส่วนใหญ่อยู่ต่ำกว่านั้น ผู้ใช้เลือก
แก้ทั้งสามจุดพร้อมกัน:

1. **Set Trap ไม่สนเกราะ** (`ignoresArmor: true` ใน `applyDamageToBoss`) — ผลข้างเคียง: เพราะไม่ผ่านการหักเกราะ
   ดาเมจจากกับดักจึง**ไม่นับเข้าเงื่อนไขเกราะแตกของ Aurelius ด้วย** (เงื่อนไขเช็ค `!opts.ignoresArmor` อยู่แล้ว)
2. **Set Trap ⏱ 5 → 4** ทั้ง Lv1 และ Lv2 — ลดต้นทุนเวลา ทำให้ประกาศได้บ่อยขึ้นและมีโอกาสให้บอสอยู่ในช่วง ⏱
   มากขึ้นด้วย (หน้าต่างสั้นลงแต่ประกาศถี่ขึ้นชดเชย)
3. **เพดานเกราะแตก Aurelius 15 → 12** (post-armor damage)

**ผลวัดจริง (balance sim, 2000 เกม, เทียบกับ baseline ก่อนแก้):**

และดาเมจต่อครั้งเพิ่มขึ้นเพราะไม่ถูกเกราะ Aurelius หักแล้ว ส่งผลต่อเนื่องให้ Aurelius clear rate และเกราะแตก
เพิ่มขึ้นชัดเจนตามที่คาดไว้ Somnivar clear rate ก็ขยับขึ้นด้วยเป็นผลพลอยได้ (Set Trap ⏱4 ยังต่ำกว่าเกณฑ์ +2
ของมนตร์ง่วงงุนที่ ⏱ ≥ 5 อยู่ดี ไม่โดนแท็กซ์)
